[ ] 1.2  DOMINIO PROPIO carniceriarauloliver.es

         en https://javieroliver-web.github.io/Carniceria-Raul-Oliver/ y el
         canonical apunta ahi, que es lo correcto mientras tanto.
         CUANDO EL DOMINIO ESTE ACTIVO, tres pasos (tambien en el README):
           1. Apuntar el DNS a GitHub Pages y activarlo en Settings > Pages.
           2. En vite.config.ts: SITE_URL = 'https://carniceriarauloliver.es'
              y base: '/'  (quitar la condicion de GITHUB_ACTIONS).
           3. Crear public/CNAME con una linea: carniceriarauloliver.es
         OJO: si se pone el dominio y NO se cambia el base a '/', la web se
         queda en blanco porque los assets se buscan en /Carniceria-Raul-Oliver/.

3. HECHO EL 6 DE SEPTIEMBRE DE 2026
--------------------------------------------------------------------------------

ERRORES CORREGIDOS
  - Canonical apuntaba a un dominio que no existe: ahora apunta a la URL real.
    La URL se define una sola vez en SITE_URL (vite.config.ts) y de ahi salen
    canonical, Open Graph, JSON-LD, robots.txt y sitemap.xml.
  - El boton "Llamar ahora" del menu movil salia gigante: .mobile-nav a (0,1,1)
    ganaba en especificidad a .btn-primary (0,1,0).
  - Las secciones quedaban tapadas por la cabecera fija al llegar desde el menu
    (scroll-margin-top: 90px).
  - El menu movil cerrado seguia siendo tabulable y lo leian los lectores de
    pantalla: ahora visibility:hidden + aria-hidden, aria-expanded en la
    hamburguesa, cierre con Esc y aria-label en la X.
  - Modales legales: role="dialog", aria-modal, cierre con Esc, scroll
    bloqueado, foco atrapado dentro y devuelto al boton de origen.
  - Tarjetas de producto: quitado el clic que no hacia nada (solo pintaba un
    borde) y que ni era accesible por teclado.
  - Contraste por debajo del minimo WCAG AA en las etiquetas de las estadisticas
    y en los enlaces del pie: corregido.
  - No habia NINGUN estilo de foco de teclado: anadido en toda la web.
  - CSS muerto del hamburger (reglas para <span> que ya no existian).

RENDIMIENTO (la pagina paso de ~2,6 MB a ~620 KB)
  - Imagenes a WebP y redimensionadas: 2,3 MB -> 604 KB. Script repetible:
    npm run images
  - loading="lazy", decoding="async" y width/height en todas las imagenes.
  - CSS de 72 KB a 15 KB (borrando shadcn/ui sin usar, theme.css, globals.css,
    fonts.css y tw-animate-css).
  - Fuentes con preconnect en el <head> en vez de un @import encadenado dentro
    del CSS; imagen del hero con preload fetchpriority=high.
  - Parallax del hero con requestAnimationFrame y desactivado con
    prefers-reduced-motion.

SEO

    og:site_name, twitter:card, theme-color.
  - JSON-LD tipo Store con direccion, telefono, email, horario, redes y mapa.
  - robots.txt y sitemap.xml generados en cada build.

  - Indicador "Abierto ahora / Cerrado" calculado con la hora de Madrid (no la

SEGURIDAD (revisada el mismo dia)
  - Vite 6.3.5 -> 6.4.3: 7 vulnerabilidades del servidor de DESARROLLO, entre

    no estaba afectado, pero la maquina de desarrollo si.
  - node-tar y sharp (0.34 -> 0.35.4, CVEs de libvips) actualizados.
    npm audit: 0 vulnerabilidades.
  - Comprobado y limpio: sin secretos en el repo ni en el historial de git,
    sin innerHTML/eval/dangerouslySetInnerHTML, 9 de 9 enlaces externos con
    rel="noopener noreferrer", workflow de despliegue con permisos minimos y
    sin interpolar entradas no confiables.
  - Corregido un preconnect a Unsplash que llevaba crossorigin y por eso no
    servia de nada (la peticion de la imagen no es CORS y no reutilizaba esa
    conexion).

RIESGO CONOCIDO QUE SIGUE ABIERTO (actualizado el 14/09)

COMANDOS
  npm run dev        servidor de desarrollo
  npm run build      comprueba tipos y genera dist/ (con robots.txt y sitemap)
  npm run typecheck  solo tipos
  npm run images     regenera webp, favicons e imagen de compartir
  npm audit          estado de vulnerabilidades

DONDE ESTA CADA COSA
  Telefono, direccion, email, horario, redes  -> src/app/data/business.ts
                                                 (el horario del JSON-LD de
                                                 index.html hay que mantenerlo
                                                 en sintonia a mano)
  URL publica del sitio                       -> SITE_URL en vite.config.ts
  Fotos: original en src/imports/, se ejecuta npm run images, y salen los
  .webp a src/assets/ y los iconos a public/
  Estilos globales, animaciones y responsive  -> src/styles/index.css

  Content-Security-Policy                     -> const CSP en vite.config.ts
  Cuando cambie la foto del hero (punto 1.1): quitar https://images.unsplash.com
  de img-src en esa CSP.

ANALITICA DE CLOUDFLARE (preparada, falta el token)
  1. Cloudflare -> Analytics & Logs -> Web Analytics -> Add a site
     (poner el dominio de la web; no hace falta mover el DNS a Cloudflare).
  2. Del fragmento que da, copiar solo el valor de "token".
  3. Pegarlo en CF_ANALYTICS_TOKEN (vite.config.ts), commit y push.
  Con el token se inyecta el script, la CSP se abre solo para Cloudflare y
  la politica de privacidad pasa a mencionarlo. Sin cookies: no hace falta
  banner.

AVISO DE ERRORES
  Los errores de JavaScript de la web llegan a Discord a traves del receptor
  del portfolio (src/errorReporter.ts -> /api/error). Si cambia el dominio
  (punto 1.2), anadirlo a ALLOWED_ORIGINS en api/error.js del portfolio.
